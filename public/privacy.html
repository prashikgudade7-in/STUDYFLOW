PRIVACY

Privacy notice

Technical review date: 19 November 2026

Draft — not ready for public launch. The service operator, contact details, retention decisions, child-user safeguards, and applicable legal terms have not been supplied or verified. The owner must complete these items and obtain qualified legal review before publishing this notice.

1. Who operates StudyFlow?

The repository does not identify the legal person or organization operating StudyFlow. Its registered or service address, privacy contact, and any required grievance contact are also not configured. This notice is not complete until the owner supplies and publishes those details.

2. Information the application handles

  • Account information: name, username, email address, class, school board, and password. The application stores a salted PBKDF2 password hash rather than the password itself. The profile may also include school, photo, and timezone.
  • Study information: tasks, schedules, events, study sessions, goals, practice progress, saved words, and other user-created records. Some record fields accept free-form text.
  • Challenge information: server-generated attempts, selected answers, score, elapsed time, class grouping, and leaderboard history.
  • Sign-in and security information: a hashed session token and short-lived hashed login identifiers used for account-level rate limiting. The application uses request IP information for in-process rate limiting; source code does not show that rate-limit IP keys are written to the StudyFlow database.
  • Notifications and choices: in-app notification content and read/important state, notification category preferences, and the version/time of recorded core-service acceptance. New notification preference rows default off.
  • Files and AI requests: the server temporarily processes PDF data to extract selectable text. Student-data AI requests are blocked while provider review is pending. A provider connection test sends only a fixed, non-student test prompt and the credential needed for that test. The browser stores selected AI provider/model/endpoint preferences, not the API key.

3. How information is used

StudyFlow uses account and study information to authenticate users, provide the study planner and practice features, save progress, calculate challenge results, and show authenticated leaderboards. It uses security information to maintain sessions and limit abusive requests. Student prompts, images and documents are not sent to AI providers because all providers remain pending. A separate connection test sends the user's provider credential and a fixed, non-student prompt to that provider.

4. AI providers and other third parties

The application offers OpenAI, Google Gemini, Anthropic Claude, Azure OpenAI, Perplexity, DeepSeek, xAI, Mistral, Cohere, and Fireworks for Meta Llama as configurable integrations. None is approved for student-data processing. The server blocks student-data requests until text, image, and document categories each have a recorded approval, verification date, and evidence reference. A valid API key does not constitute approval, and the application does not switch to a fallback provider. The optional connection test is separate: it rejects user-supplied prompts, images, and documents and sends only a fixed non-student test prompt. No provider retention, training, review, or data-region practices are represented as verified. See the [AI provider approval register](../docs/AI_PROVIDER_APPROVAL_REGISTER.md).

DM Sans and Manrope are now served from the StudyFlow site, with their SIL Open Font License included in the repository. No analytics, advertising SDK, tracking pixel, or nonessential cookie was identified in the reviewed application source. Hosting-provider processing and access logs depend on the deployment and are not configured by this repository.

5. Storage and retention

  • SQLite stores account data, study records, sessions, challenge attempts and results, notifications, preferences, and consent records. The application has no general automatic retention schedule for accounts, study records, completed challenge history, or notifications.
  • Server-side sessions expire after 14 days. Account creation uses a persistent 14-day browser cookie. On later sign-ins, unchecking “Keep me signed in” requests a browser-session cookie; the corresponding server session still expires no later than 14 days.
  • Login-rate-limit identifier hashes are short-lived (15 minutes) and stale rows are cleaned up periodically.
  • Challenge question sets and answer keys are stored temporarily for scoring and removed by hourly cleanup after attempt expiry. A minimal daily anti-replay marker is retained through the current IST date and removed by cleanup after the date changes.
  • PDF input is processed in memory by the extraction endpoint rather than intentionally saved as a file. Student content is not forwarded to an AI provider while provider approvals are pending.
  • The application does not intentionally save AI API keys, prompts, or submitted images to its SQLite database. Connection tests can transmit the selected API key and a fixed non-student prompt to the selected provider. Deployment backups and infrastructure logs require separate owner configuration and review.

6. Cookies and browser storage

The first-party studyflow_session cookie is used to authenticate a signed-in session. It is HttpOnly, SameSite=Lax, and Secure when served over HTTPS. See the cookie notice for the current inventory.

The browser stores a non-cookie preference named studyflow_ai_pref in localStorage. It contains the chosen provider, model, and optional Azure endpoint; it does not contain the API key. It remains until cleared in the browser.

7. Access, correction, export, and deletion

Signed-in users can download a JSON export containing their profile, study records, challenge history, notifications, notification preferences, recorded core-service consent and browser AI-provider preferences. Password hashes, session tokens and answer keys are excluded. Settings also allows users to clear their study records or challenge history without deleting the account. To prevent a same-day challenge replay, clearing challenge history retains a minimal current-day claim until the IST date changes and cleanup runs. Account deletion requires the current password and removes the account's active SQLite data, including its consent record. Application deletion does not remove deployment backups, platform logs, or information already sent to a third party. The operator must publish a functioning privacy contact and define backup deletion and request-handling procedures before launch.

New accounts must affirmatively accept the stated core-service data-use purpose. Optional notification preferences are off for new preference rows. No AI-content consent is requested while providers and their terms/regions/retention remain unverified; the application blocks student-content AI requests.

8. Children and student information

The owner has specified an intended minimum age of 18, with users under 18 eligible only through parent/guardian consent and controls. The current build does not implement age verification or a guardian consent workflow, so it does not yet enforce this policy. Do not treat this draft or the current registration form as an age or guardian-control mechanism; these controls and legal review are required before enrolling users under 18.

9. Security and changes

The application uses password hashing, hashed session tokens, authenticated routes, rate limits, and HTTPS-aware cookie settings. These are technical controls, not a guarantee of security or legal compliance. No claim is made that data is encrypted at rest; storage, backups, access controls, and incident handling depend on deployment configuration.

Before this notice is published as an operational policy, the owner must add the operator identity and contact details, define retention and backup deletion, verify provider approvals and transfers, implement age/guardian controls, select hosting and operational practices, and obtain legal review. Official current DPDP commencement texts were not retrievable during the technical review; counsel must verify the rules and effective provisions before launch. This draft must be updated if the service or its data practices change.

10. Contact

No privacy contact or operator address is configured in the project. The owner must supply a monitored contact channel and any legally required details before publication.
